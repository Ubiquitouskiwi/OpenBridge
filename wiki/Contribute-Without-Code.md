# Ways to help without code

You do not need to be a programmer to make OpenBridge better. This page lists every way to help
that needs no code, how long each one takes, and the best place to start. It is for social workers,
navigators, legal aid staff, policy researchers, translators, and accessibility testers.

> **OpenBridge is a prototype.** All three states (Ohio, Texas, Washington) use draft rules that
> no expert has checked yet. Your help is what turns those drafts into rules people can trust.

## The best first task

If you have one hour, [[record a test case|Record-a-Test-Case]]. Pick a made-up household that
looks like the families you see most often. Screen it in OpenBridge, say what result you expect for
each program, and send us the file. Each test case is checked every time the rules change, so it
keeps protecting families long after you send it.

## How to get started

Most help happens on GitHub, the website where OpenBridge's files and discussions live. An
"issue" on GitHub is a public note that reports a problem or asks a question.

1. Create a free GitHub account at [github.com/signup](https://github.com/signup). You only need an
   email address. You do not need to install anything.
2. Go to the OpenBridge repository page and choose the **Issues** tab.
3. Choose **New issue**. Pick the form that fits: "Eligibility rule correction", "New state request
   or offer", "Bug report", or "Feature request".
4. Fill in the form and submit it. A maintainer will reply on the issue.

Prefer not to use GitHub? Email openbridge@starlingtek.com. Say what you want to help with, and we
will post your report or file for you and keep you updated.

## Ground rules

- **Never share real people's details.** Use made-up households with round numbers. This applies
  to issues, emails, test cases, and screenshots.
- **Cite official sources.** A rule value should point to an agency page, policy manual, or
  published table. See [[Report a rule problem|Report-a-Rule-Problem]] for what makes a good source.
- **Only experts verify.** Anyone can report a problem, but only a subject-matter expert can mark
  a state's rules as checked. See [[Review rules as an expert|Review-Rules-as-an-Expert]].
- **Security or privacy problems go privately.** Do not open a public issue. Follow the
  [security policy]({{repo}}/blob/HEAD/SECURITY.md).
- Everyone follows the [code of conduct]({{repo}}/blob/HEAD/CODE_OF_CONDUCT.md).

## What happens next

A maintainer reads every report and file. Rule changes are checked against the source you cite,
and a subject-matter expert reviews them before a state can be marked verified. You can follow
along on the issue and see what was changed.
